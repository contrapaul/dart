# ED-35 requests

Two small changes in files ED-35 does not own. Both have a working
workaround in this branch, so nothing is blocked.

## src/editor/view.ts: a marker's resources are disposed when it rebuilds

`disposeTree` disposes every marker's and ghost's geometry and materials.
A placed model shares the loaded scene's geometry and materials, so ED-35
copies both for each marker and ghost (`ownResources` in
`src/editor/models-editor.ts`). That is a few kilobytes per cube and up to
a few hundred thousand triangles per redraw for a dense model, which will
show on a big imported model.

Ask: skip the dispose for an object marked with `userData.shared = true`,
or give `addMarker` and `setGhost` an option not to dispose. Then the model
marker can use the shared scene directly.

## src/level/breakables.ts: Breakables is prim-only

ED-06's `Breakables` builds its mesh from `primGeometry` and keys its state
by `prim`. A model has a GLB mesh and no prim, so ED-35 wrote
`ModelBreakables` in `src/level/model-voxels.ts` with the same dart, blast,
swing and reset surface, and `src/arena/extras.ts` calls both.

Ask: let `Breakables` take a mesh and colliders from any source (a prim or a
model), or export the hit point, blast and swing bookkeeping so a second kind
of thing reuses it rather than a near copy. Until then the two lists are
kept in step by hand in `extras.ts`.

## ED-31: the move registry is not in this tree yet

The card says to register each model with ED-31's move registry if it
exists. It does not exist in this branch. Every model, a hidden one and a
hidden breakable one included, has a `setShown` handle in
`BuiltLevel.models.handles`, which is the same map the trigger show and hide
path reads. When ED-31 adds `move`, a model's handle should carry the
transform so a move can reach it.
