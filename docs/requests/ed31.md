# ED-31 requests

## The mover cannot move a breakable or a hazard prim

`src/level/validate.ts` lets a `move` name any prim id, and a breakable or a
hazard prim is a prim id. Those two kinds are not built by
`src/level/prims.ts` (ED-06's `Breakables` and ED-03's `Hazards` build them),
so they never get a `PrimHandle.move` and the move does nothing.

If they should move, their owners need to register with the mover:
`ArenaExtras.movers` (`src/arena/extras.ts`) is the registry, and one call
per thing is enough:

```ts
movers.register(id, (x, y, z, turn) => { /* put the mesh and its colliders */ });
```

Best done where each kind is already handed the level: an optional
`registerMovers(movers)` on `Breakables` / `Hazards`, called from
`arenaExtras`, keeps ED-31's file out of it.

Alternatively the validator could refuse a move on those ids until they can
move. That is a one line change in the `movable` set in `validate.ts`, and
it is not mine to make.

## ED-32, ED-33 and ED-35

The registry is exposed as `movers` on `ArenaExtras`, so a light, a physics
object or a model plugs in without editing `src/arena/extras.ts`:

```ts
movers.register(id, (x, y, z, turn) => { /* set the transform */ });
```

A button mounted on one of those (`Button.on`) then rides on it, because
`extras.ts` attaches buttons to the id `on` names.
