## Result

Done. The rename works end to end and is one undo step per rename.

What works, with the command that proves it:
- Pure rename, `src/editor/rename.ts`: `applyRename` and `renameProblem`.
  `npx vitest run tests/editor/rename.test.ts` (14 tests, all pass).
- `LevelDoc.rename(oldId, newId)` (`src/editor/doc.ts`): one undo step,
  status-shaped problem string or null. Covered by the same test file
  (undo and redo of a rename, a refused rename recording nothing).
- Every single-selection inspector shows the id at the top as an editable
  name: prims (kept, commits through the doc), Foamers, pickups, doors,
  spawn points, zones, props, lights, physics objects, models, buttons,
  triggers. Not the start, the exit, terrain, or the sky. Commits on Enter
  or leaving the field; refuses with a status message.
  `.swarm/preflight.sh` green.
- Double click on an outliner row (prims, parts, triggers) edits the name
  in the row itself: Enter commits, Escape or leaving cancels. Clicking
  away while the field still holds a valid, unchanged id resets quietly.
  The selection follows the new id (selection set, outliner, inspector
  and view link set all rebuild).

Not verified (a person should look):

  Same for a double click on an outliner row; and try a refused rename

- Renaming a trigger that is named by an `after` clause of another

Decisions the plan did not settle:
- The spawn row's own tag is left alone when a spawn point is renamed:
  the tag is the row's name, not a reference to another thing, and it is a
  separate claim in the validator. Renaming a spawn point therefore only
  rewrites the `at` lists that name it.
- Model assets are not rename targets through this path (they are not
  editor entry kinds); `applyRename` still repoints placed models when an
  asset id is rewritten, so nothing is left pointing at a dead id.
- The "valid id" rule is `/^[A-Za-z0-9][A-Za-z0-9_-]*$/` (letters, numbers,
  dashes, underscores, starting with a letter or number). Names the
  validator itself does not forbid; the validator claims uniqueness only.
- `LevelDoc.rename` returns the problem string (or null) rather than a
  boolean, so the editor can show the reason in the status line.
