   Images are scaled down to the cap with a canvas, as the sky is. Uploads
   appear in the Paint panel's swatches, the prim surface select and the

## Result

Done. Uploaded textures and tilesets: format, validator, registry, editor
wiring and tests are built and committed.

What works:
- `Level.textures?: TextureAsset[]` in src/level/format.ts: id, name, image
  (data: URL), scale. The validator checks count (16), each image's size
  (512 px a side, parsed from PNG/JPEG headers), bytes (300000), scale, and
  that `tex:<id>` surfaces on prims, physics objects and terrain layers name
  an existing texture (tests/render/textures.test.ts).
- `setLevelTextures(list)` in src/render/surfaces.ts registers the uploads;
  `SURFACES` and `SURFACE_NAMES` gain the `tex:<id>` entries (label and
  scale), `isSurface` accepts them, and `surfaceTexture`/`surfaceMaterial`
  resolve them as an image texture (RepeatWrapping, sRGB, tinted by the
  colour, cached per upload). The game calls it at the top of `buildLevel`
  (src/level/build.ts); the editor calls it at the top of `redraw`
  (src/editor/main.ts).
- The level inspector (nothing selected) has a Textures section: file input
  (png or jpg), name, scale (metres a repeat) and a tiles-across x tiles-down
  pair (default 1x1) that cuts an upload into that many textures ("name 1",
  "name 2", ...), each kept in the level file as a data: URL. Images are
  scaled down to the cap with a canvas, as the sky is. Each texture has its
  own name input (rename), scale input and Delete button.
- Uploads appear in the Paint panel's swatches (the swatch draws the image),
  the prim surface select and the terrain layer selects (raw value, label
  from the registry, plus the name shown for uploads).

Proof: `.swarm/preflight.sh` is green (type check, 218 test files, dash check).
The upload flow itself is not browser-verified: look at the editor, nothing
selected, and check the Textures section; upload a png (and a 4x2 tileset),
check each texture shows in the list, in the Paint panel, in the prim and
terrain layer selects; undo an upload; play the level and check the texture
tiles at the scale it says.

Unfinished / notes:
- The Textures section has no CSS of its own (editor.css untouched, not in
  this card): it is plain stacked fields. Worth a look in a browser.
- The physics objects' surface select shows the raw `tex:<id>` value, not the
  texture name (its editor file is not in this card).
- Deleting a texture that a prim still references leaves the broken reference
  in the level: the validator refuses that level, and the problems panel says
  so. Cleared references automatically would be surprising magic.
- Uploads are jpeg data: URLs after a canvas re-encode, so they lose alpha.
  Alpha would mean keeping the original png bytes past the 300 KB cap.
