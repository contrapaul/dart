## Build, one commit per step

1. **Groups fold (item 1).** Every `h2` group title in the outliner
   (`buildOutliner`: the prim behaviour groups, the part groups, Logic,
   Level) gets a small triangle and folds its rows on click. Folded groups
   are remembered per group title in a module level `Set` (survive a
   redraw) and in `localStorage` key `dart-editor-folded` (wrap every read
   and write in try/catch). A folded group shows its count after the title,
   for example "solid (42)". Selecting a thing in the view unfolds its
   group so the selected row is seen. Keyboard: the title is a `button`,
   so Tab and Enter work.
2. **Lock (item 3).** `locked` is on `Prim`, `Prop`, `PhysicsObject`,
   `PlacedModel` and `Terrain` already (`src/level/format.ts`). Each row of
   those kinds gets a lock button next to the eye (an inline SVG padlock in
   `src/editor/icons.ts`, `aria-pressed`), one undo step per toggle through
   `doc.change`. The inspector gets a "locked" checkbox for one selected
   thing. A locked thing: `view.pick` passes through it (add the locked ids
   to the skip set the pick already takes), box select skips it, the handles
   do not attach to it, Delete and the arrow or turn keys leave it alone,
   and the status line says "<id> is locked" when an action skips one. It
   can still be picked in the outliner, to unlock or read it. Drawn the
   same as unlocked (no tint): Paul asked to lock, not to hide.
3. **The start turns (item 11).** The player start can be selected but its
   facing only changes in the inspector's yaw box. Let the rotate handle
   (Y only) and the `[` `]` turn keys turn it, the way they turn a Foamer.
   `PlayerStart.yaw` is radians, `0` faces -z; the marker's nose must point
   where the player will look. Check by reading the marker code and by a
   test of the yaw maths.
4. **Rotation snap (item 12).** Today every rotation snaps to
   `rotateStep` (15) from `data/editor.json`, and only G turns all
   snapping off. Add a rotation snap choice to the top bar (a `select`:
   off, 1, 5, 15, 45, 90; default from `rotateStep`), used by the rotate
   handle (`setRotationSnap`), by `snapPrim`'s rotation and by the
   inspector's rotation number boxes' step. Remember the choice in
   `localStorage` (`dart-editor-rotate-snap`, try/catch). G still turns all
   snap off and on. A rotation typed into the inspector is kept exactly as
   typed, never snapped.

## Result

What works, with the command that proves it

- Folding: `src/editor/outliner-fold.ts` holds the folded titles in a module
  Set, saved to localStorage `dart-editor-folded` (all I/O in try/catch), and
  read back on every redraw. `buildOutliner` renders each `h2` title as a
  real button with a triangle; a folded group shows its count ("solid (42)"),
  Tab and Enter work, and selecting a thing in the view unfolds its group.
  Proven by `npx vitest run tests/editor/ed30.test.ts` (5 fold tests).
- Locking: `src/editor/lock.ts` collects lockable kinds (`prims`, `props`,
  `physics`, `models`) into a set. The outliner's prim and prop rows have an
  inline SVG padlock (`aria-pressed`, one undo step per toggle), the
  inspector gets a "locked" checkbox for one selected thing (prims appended
  from `buildPrimInspector` since inspector.ts is not this card's file; props
  in `inspector-parts.ts`). Locked things are skipped by `view.pick` (a
  `lockedSkip` set the page hands over each redraw, unioned with the pick's
  own skip set), left out of box select, drawn but without handles (the
  handles detach in `view.select`), and left alone by Delete and the turn
  keys, which say "<id> is locked" in the status line. Proven by the lock
  tests in `tests/editor/ed30.test.ts` and `.swarm/preflight.sh` (200 files,
  1580 tests green).
- The start turns: the rotate handle (Y only: the X and Z rings and the ring
  pairs are hidden) and the `[` `]` keys turn the player start, like a
  Foamer. `dragPatch` writes its yaw in radians, 0 faces -z; the marker nose
  cone (built in `markers.ts`, pointing -z at yaw 0) points where the player
  will look. Proven by the two start tests in `tests/editor/ed30.test.ts`
  (`dragPatch` with kind `start`). Inspector's yaw box is unchanged apart
  from the new snap step.
- Rotation snap: top bar select (off, 1, 5, 15, 45, 90), remembered in
  localStorage `dart-editor-rotate-snap` (try/catch). It feeds `view.setRotationSnap`,
  `snapPrim` (the page passes it as the rotateStep argument) and the
  inspector's rotation number boxes' step (doors, props, Foamers, start; prim
  rotation is requested in `docs/requests/ed30.md`). G still turns every snap
  off and on. A typed rotation in a box is committed untouched. Proven by the
  snap tests (each step, and off) in `tests/editor/ed30.test.ts`.
