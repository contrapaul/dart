# FX-01: a visible blast for every explosion

Written 2026-11-13. Paul: "At present the explosion happens, but the only
'effect' we see is B07's lame 'mortar firing' type effect. Explosions
should have a visible blast, ideally one that can scale and which has only
a minor impact on performance. This applies to B07 as well as any
explosive mods. It would also be able to be reused later for explosive
terrain elements."

## What is there today

- `src/weapons/explosion.ts` `ExplosionSystem.explode(point, profile,
  clustered)` does the damage, the carve, the push and a burst of foam
  chunks (`debris.burst`), then calls `onExplode(point)`. Profiles in
  `data/explosion.json`: `dart` (B05 explosive mod, B06 every fifth shot),
  `launcher` (B07), `cluster` (B07's cluster mod, four small blasts).
- The only thing you see is that chunk burst. `game.ts` hooks
  `onExplode` for the `FX-explode` sound; the range does not hook it.

## What to build

1. **The effect.** `BlastFx` in `src/render/blast-fx.ts`, one per page,
   added to the scene. `spawn(point: Vector3, radius: number)` shows one
   blast whose size follows `radius` (metres), so the same call serves a
   small dart blast, B07's round and, later, an exploding barrel. The look,
   all from `data/explosion.json` `fx`:
   - a bright core flash: a sphere that swells fast from small to about
     the radius and fades out (additive or plain transparent, no lighting),
   - a foam puff: a soft white shell that swells past the radius more
     slowly and fades, so the blast reads as a ball of foam bursting,
   - a flat ring along the ground or a shock shell is optional; only if
     it stays cheap.
   Durations are short (start near 0.12 s for the flash, 0.4 s for the
   puff). Colours start bright yellow-orange core and foam white; it is a
   foam game, so no fire, no smoke column, nothing scary. Paul will judge
   the look; keep every colour, time and size in data.
2. **Cheap and capped.** A fixed pool (`fx.maxLive`, start 12), built
   once: shared geometry (one low-poly sphere, about 16 by 12, and one ring
   if used), one material per layer per slot or per-instance colour, no
   allocation per spawn or per frame, no real lights, no shadows
   (`castShadow` and `receiveShadow` false), `depthWrite` false. When the
   pool is full the oldest slot is reused. Hidden slots are not drawn.
3. **Timing is pure.** Put the curve (scale and opacity against age, for
   each layer) in a pure function with no THREE or DOM, so it is tested
   headless. `BlastFx.update(dt)` advances ages; run it from the page's
   render hook so it follows frame time, not the fixed step. While the
   game is paused the blast freezes with everything else.
4. **Wire it.** `onExplode` gets the profile's visual size as a second
   argument: a new `fxRadius` per profile in `data/explosion.json` (start
   at about 0.8 of `rangeMetres`). `game.ts` keeps the sound and also
   spawns the blast; the range spawns it too. Every explosion goes through
   `explode`, so B07, its clusters and the B05 and B06 explosive mods all
   show it.
