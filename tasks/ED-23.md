# ED-23: saved assets

Written 2026-11-17. Paul asked for three things in the builder: copy and
paste, a way to combine geometry together, and a way to save assets.
The first two were built in ED-13 (copy, cut and paste on the system
clipboard; Ctrl+G makes a group that selects, moves and copies as one).
Saving a built piece to use again is not built. It was "ED-23 Stamps" in
Plan M of `design/EDITOR-OVERHAUL.md`, which did not go ahead. This card
brings it forward on its own, without Plan M's picture palette.

## What to build, in stages (commit each)

1. **The asset and its store.** An asset is a name, a clip (the same
   `dart-clip` entries a copy makes), and a small picture. Assets live
   in this browser (IndexedDB, beside the levels) and belong to no one
   level. Save, list, rename, delete. A hard cap on how many assets and
   on how many things one asset holds, as numbers in `data/editor.json`.
2. **Save.** With things selected, "Save as asset" asks for a name and
   stores the selection. The picture is taken from the editor's own
   view of just those things. The start and the exit are never saved,
   as with copy.
3. **The panel and placing.** A panel shows the assets as pictures with
   their names. Picking one places it under the cursor with the ghost
   preview, snapped like a paste, as one group and one undo step. A
   place that would go over a level cap is refused with the reason.
4. **Files.** Export one asset or all of them as a JSON file, and import
   a file. A file that is not ours, or is a newer version, is refused
   with the reason. An imported asset whose name is taken gets a new
   name, never replaces one.

## Rules

- No asset ships with the game unless Paul makes it. Names are his.
- Nothing is fetched from another host. Pictures are made in the
  browser and stored as data.
- An asset's picture must not hold the frame up: make it once on save.

## Open questions for Paul

1. **What "combine geometry" should mean.** Answered (Paul,
   2026-11-17): a group is enough. Ctrl+G from ED-13 is the combine. No
   true merge into one shape is planned.
2. **Where assets live.** This card keeps them in the one browser, with
   files to move them. They are not shared between machines by
   themselves.
3. **Should a group show in the panels?** A grouped thing has no mark
   in the outliner or the inspector yet (known from ED-13).

## What changed while building (2026-11-17)

- Built in the `ed-12` worktree on top of ED-14, not on its own branch.
- Assets have a database of their own (`dart.assets`), so
  `src/editor/store.ts` and the levels' database are not touched.
- The panel is a dialog behind an Assets button in the top bar, not a
  panel that stays open.
- `src/editor/clipboard.ts` gained `pasteMove`, taken out of `pasteClip`,
  so the ghost sits where the asset will land.
- A placed asset is one new group. Groups inside it are not kept apart.
- A picture in an imported file is kept only when it is a small PNG or
  JPEG held in the file itself. Anything else is dropped.
- Delete has no "are you sure", the same as deleting a level.
