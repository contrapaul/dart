## What was found (reviewer)

- **The lock comes before the game.** `Input` is built early and its
  canvas `click` listener takes pointer lock straight away. While the
  page is still booting (the module chain awaits Rapier, the blaster
  models, the Foamer meshes), the click hides the cursor, but no frame
  loop reads the mouse yet, so the camera does not turn. That is exactly
  Paul's "you lose it, but don't control the camera".
- **Firefox boots slowly.** Headless Firefox here took 20 to 30 s to
  boot the live range against about 3 s in Chromium, while each model
  fetch finished in under a second. Where the rest goes in Firefox is
  not known: the Foamer meshing (worker or main-thread fallback, PT-09),
  the GLB parse, the shader compile, Rapier, something else.
- **The range hides boot errors.** `boot-errors.ts` writes into
  `#status`, which `range.html` does not have, so a failed range boot
  shows only in the console.

## What to build

1. **Boot report.** Each page records its boot in named steps with the
   time each took (`performance.now()`): at least Rapier ready, each
   blaster model loaded, the loadout ready, level or range built, every
   Foamer's meshes done (count done of total), first frame drawn. Show
   the current step in the page's status line while it boots ("Loading
   blasters 3 / 8", "Building Foamers 9 / 16"), and log one
   `DART boot: <step> <ms>` console line per step. With `?diag`, keep a
   small readout up after boot with: the browser, the mesher mode
   (workers and how many, or main thread) and fallback count (PT-09),
   and each step's time. Cheap, no allocation per frame.
2. **Range status line.** `range.html` gets the same `#status` element
   the game pages have, so boot progress and boot errors show there.
   Keep `tools/smoke.mjs`'s range ready check meaningful (it waits for
   the blaster label to name B01 today).
3. **No lock before the game runs.** `Input` ignores a click for pointer
   lock until the page says the game is running (the first frame has
   been drawn). Until then the status line says it is loading and the
   cursor stays. Keep the PT-09 Firefox lock behaviour exactly as it is.
