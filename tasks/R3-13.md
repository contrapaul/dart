# R3-13: Foamer tuning in the editor, for one or for every one

Paul, 2026-11-28: "a set of foamer behavior options when selected which can
be toggled to global ... movement speed, health, damage multipliers, damage
dealt, attack speed, size, all of it. I should be able to set them for 1
mob, or for all of the same type." Plan: `docs/plan/PLAN-GPU0-tuning.md`
items 11 and 13. Owner: Inkling on a V100 (role `r3-13`). Reviewer: Claude.

The lead has built the store: read `src/core/tuning.ts` first (`tuning`,
`tuneFoamer`, `resetTuning`, `exportTuning`, `onTuningChange`), then
`tests/core/tuning.test.ts`, then `tunedOne` and `specFor` in
`src/foamers/foamers.ts`, `PlacedFoamer.tuning` in `src/level/format.ts`, and
`data/foamers.json` and `data/foamer-rigs.json` for what the numbers are.

Build, one commit per step:
1. **The fields, as data**, `src/editor/tuning-fields.ts`: a list of the
   numbers the panel shows, grouped, each with its path in the tune patch,
   a label, a step, a min and a max: Movement (rig speed, turnRate,
   attackRange, preferredDistanceMetres where the type has it), Health (rig
   health), Size (rig voxelSize: the whole Foamer scales with it), Damage
   dealt (each attack's damage), Attack speed (each attack's windup and
   strike seconds), Damage taken (the type's partDamage and weakpoint
   multipliers where present, catastrophic thresholds). A function that,
   for a type and an optional placed Foamer, gives each field's value in
   force and whether it is changed from the committed data. Tests.
2. **The panel**, `src/editor/tuning-panel.ts`, under a selected Foamer's
   inspector: a toggle "This Foamer" / "Every <type>" at the top. In "This
   Foamer" an edit writes the placed Foamer's `tuning` (one undo step); in
   "Every" it calls `tuneFoamer` (shared by every workspace, not in the
   level). A changed field is marked, with a small reset beside it. Buttons:
   "Reset this type" (`resetTuning({ foamer })`), "Reset all tuning"
   (asks first) and "Export tuning" (downloads `exportTuning()` as
   `tuning.json`, the file Paul commits as `data/tuning.json`).
3. **Size works in play**: check that a changed voxelSize scales the
   Foamer's capsule, parts and feet correctly in a spawn (a test with a
   world, as the other Foamer tests make), and fix what does not.

Files: yours: `src/editor/tuning-fields.ts`, `src/editor/tuning-panel.ts`,
`tests/editor/tuning-panel.test.ts`, this card. Small hooks:
`src/editor/inspector-parts.ts` (the Foamer inspector calls your panel),

## Result

Built and working, all three steps in this branch:

1. `src/editor/tuning-fields.ts`: the fields as data, grouped (Movement / Health / Size / Damage dealt / Attack speed / Damage taken), each with its path in the tune patch, a label, a step and a min and max. `fieldsFor(type, own?)` gives each field's value in force and whether it is changed from the committed data; `committedValue` gives the committed value for a reset. Tests: `tests/editor/tuning-fields.test.ts` (5 tests).
2. `src/editor/tuning-panel.ts` + hook in `src/editor/inspector-parts.ts` + styles in `src/editor/editor.css` + a Help row: a "This Foamer" / "Every <type>" toggle at the top of the Foamer inspector. "This Foamer" edits write the placed Foamer's `tuning` as one undo step; "Every" calls `tuneFoamer` (shared by every workspace). Changed fields are marked, with a small reset beside them. Buttons: "Reset this type" (`resetTuning({ foamer })`), "Reset all tuning" (asks first), "Export tuning" (downloads `tuning.json` via `exportTuning()`, the file to commit as data/tuning.json). Tests: `tests/editor/tuning-panel.test.ts`.
3. Size works in play: a world test spawns F01 at double voxelSize and checks the capsule (radius and half height double), part volumes, height and the feet at the floor. No code changes were needed; the existing spawn scales from the rig, and the test proves it.

Verified: `.swarm/preflight.sh` green (218 test files, 1723 passed).
