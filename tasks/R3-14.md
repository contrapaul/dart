Paul, 2026-11-28: "Player weapon details should also be tunable." Plan:
`docs/plan/PLAN-GPU0-tuning.md` items 12 to 14. Owner: Inkling on a V100
(role `r3-14`). Reviewer: Claude.

The lead has built the store: read `src/core/tuning.ts` first (`tuning`,
`tuneBlaster`, `resetTuning`, `exportTuning`, `onTuningChange`) and
`tests/core/tuning.test.ts`, then `resolveSpec` in `src/weapons/blaster.ts`,
`data/blasters.json`, `data/melee.json`, and the range page
(`range.html`, `src/range/main.ts`, `src/range/menu.ts`).

Build, one commit per step:
1. **The fields, as data**, `src/range/blaster-fields.ts`: the numbers a
   blaster has, grouped (Fire: mode-specific fireInterval, spinUp,
   dartsPerShot, spreadDeg, recoil; Ammo: magSize, reserveMax,
   reserveStart, reloadTime, primeTime; Movement: fireMoveShare; Damage:
   the dart type's damage lives in data/darts.json and is not per blaster:
   leave it out and say so), each with path, label, step, min, max, and the
   value in force. Tests.
2. **The panel**, `src/range/tune-panel.ts`: a "Tune" section in the
   range's panel for the held blaster: every field, changed ones marked
   with a reset beside them, edits through `tuneBlaster` (so the editor,
   the arena and play use them too), "Reset this blaster", "Reset all
   tuning" (asks first), "Export tuning" (downloads `exportTuning()` as
   `tuning.json`). The held blaster picks up the change at once: rebuild it
   with `resolveSpec` on `onTuningChange`, keeping its ammo where it can.
3. **Every workspace**: a small "Tuning: changed" note with a Reset button
   on the arena's pause panel when this browser's override is not empty
   (`localTuning()`), so a student on a school computer can put the game
   back.

## Result

Built and tested. Three commits:

1. `src/range/blaster-fields.ts` plus `tests/range/tune-panel.test.ts`: the fields as data, grouped Fire (fireInterval, spinUp, dartsPerShot, spreadDeg, recoil.spreadPerShot), Ammo (magSize, reserveMax, reserveStart, reloadTime, primeTime) and Movement (fireMoveShare). Each carries path, label, step, min, max, and the value in force. No per-blaster damage field: damage lives in data/darts.json per dart type, not per blaster. `fireInterval` and `spinUp` are auto/semi features (the pump blaster uses primeTime), and the recoil edit is spread-per-shot only, the rest of the recoil block stays in data.
2. `src/range/tune-panel.ts` plus `range.html` (a "Tune" section in the default menu, not bench tools), `src/range/main.ts` (a `TunePanel`, an `onTuningChange` that rebuilds every blaster through the new `Loadout.rebuild`, a re-render on a blaster switch) and `src/weapons/loadout.ts` (`rebuild(i)`, keeping reserve, magazine capped by the new magSize, dart type and shots). Every edit goes through `tuneBlaster`; a changed field shows a Reset beside it (reset writes the committed value back, so the marker clears); "Reset this blaster", "Reset all tuning" (asks first) and "Export tuning" (downloads `exportTuning()` as `tuning.json`) are at the foot of the section.
3. `arena.html` plus `src/game/ui.ts` (`#tuningNote` in the arena's pause panel, guarded so the test course page is untouched): a "Tuning changed on this browser" note with a Reset button whenever `localTuning()` is not empty, wired on show and on every tuning change.

Tests: `tests/range/tune-panel.test.ts` (6 cases, pure). `.swarm/preflight.sh` green before every commit (1720 passed).

In the browser to look at: open `range.html`, Esc, find the Tune section, drag a slider, watch the blaster and HUD change, check a changed field gets its Reset, then Reset this blaster / Reset all tuning (with the confirm) and Export tuning (downloads tuning.json). Open `arena.html`, play and Esc, and after a range tuning change, check the note and its Reset in the pause panel.
